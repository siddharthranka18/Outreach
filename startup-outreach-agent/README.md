# Startup Job Outreach Agent

A modular, personal automation system designed to discover early-stage startups and identify software development internships or potential internship opportunities.

---

## Current Status: Prompt 2 (Database Persistence & Models)

The application includes:
- **Relational Persistence Layer**: SQLAlchemy 2.x models for `companies` and `jobs` with foreign key enforcement.
- **Deduplication & Normalization**: Canonical website domain extraction, tracking-stripped job URLs, and name normalization.
- **Repository Pattern**: `CompanyRepository` and `JobRepository` with atomic transactions, non-null preserving upserts, and querying.
- **Database Migrations**: Alembic setup with autogenerated migrations and SQLite batch support.
- **Clean Architecture Separation**: Pure dataclasses (`Company`, `Job`) in the domain layer, separate from SQLAlchemy persistence models (`CompanyModel`, `JobModel`).
- **Test Suite**: 22 unit & integration tests covering persistence, foreign keys, deduplication, and isolation.

> **Note:** Web scraping, LLM scoring/drafting, Telegram alerts, and automated email sending remain intentionally deferred to subsequent prompts.

## Setup & Database Migrations

### 1. Prerequisites
- Python 3.11+
- Git

### 2. Virtual Environment Setup
```bash
cd startup-outreach-agent

# Create and activate virtual environment
python -m venv .venv

# On Windows (PowerShell):
.venv\Scripts\Activate.ps1

# On Linux/macOS:
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Copy environment template
cp .env.example .env
```

### 3. Run Database Migrations
To apply database migrations:
```bash
alembic upgrade head
```

To create a new migration after model changes:
```bash
alembic revision --autogenerate -m "describe changes"
```

## Running Tests

Run the complete test suite:

```bash
pytest
```

For verbose output:

```bash
pytest -v
```

> **Note on Test Isolation:** Tests use in-memory SQLite (`sqlite:///:memory:`) configured with isolated table lifecycles. Running tests never affects the actual application database.
